## Skill Loading

Before editing files for a substantial task:
- Run `pnpm dlx @tanstack/intent@latest list` from the workspace root to see available local skills.
- If a listed skill matches the task, run `pnpm dlx @tanstack/intent@latest load <package>#<skill>` before changing files.
- Use the loaded `SKILL.md` guidance while making the change.
- Monorepos: when working across packages, run the skill check from the workspace root and prefer the local skill for the package being changed.
- Multiple matches: prefer the most specific local skill for the package or concern you are changing; load additional skills only when the task spans multiple packages or concerns.

## Feature Workflow

For feature or fix work, use the local `feature` skill in `.codex/skills/feature/`.

Standard lifecycle:

1. `feature load <spec path or description>`
2. `feature start`
3. `feature test`
4. `feature review`
5. `feature complete`

`feature explain` is optional.

Rules:

- Treat `context/current-feature.md` as the source of truth for active scope.
- Every implementation change must map to an acceptance criterion.
- Run `pnpm check` before feature testing and review; use `pnpm check:fix` only when file changes are intended.
- Do not implement a feature until it has been loaded and documented.
- Do not complete a feature unless its status is `Ready to Commit`.
- If testing or review fails, keep the status `In Progress`, fix the issues, and repeat `feature test` and `feature review`.
- Preserve `## History` as append-only.
- Follow `context/ai-interaction.md` for branching, communication, scope, and verification rules.

## Scaffold

- Project: `1000-pomodoros`
- Scaffold source: TanStack CLI blank React starter
- Exact command: `npx @tanstack/cli@latest create 1000-pomodoros --agent --package-manager pnpm --tailwind`
- The command was run in a scratch directory because the actual project directory already existed as an empty Git repository; the generated project was then merged into this repository without the scratch `.git` directory or `node_modules`.
- The CLI reports that `--tailwind` is deprecated and ignored because current TanStack Start scaffolds always include Tailwind.

## Stack and Integrations

- React 19 with TanStack Start and file-based TanStack Router
- Vite and TypeScript using the default CLI toolchain
- pnpm package manager
- Tailwind CSS v4 through `@tailwindcss/vite`
- TanStack Devtools and Router Devtools from the default scaffold
- Vitest, Testing Library, and jsdom from the default scaffold
- Biome for formatting, linting, and import organization
- No application integrations, data layer, authentication, API routes, or feature scaffolding

## Architecture

- `src/routes/__root.tsx` owns the HTML document shell and must retain `HeadContent` in `<head>` and `Scripts` in `<body>`.
- `src/routes/index.tsx` is intentionally blank except for an empty `<main />`.
- `src/routeTree.gen.ts` is generated by TanStack Router. Do not edit it manually; run `pnpm generate-routes` or let the Vite plugin regenerate it.
- Code is isomorphic by default. Use `createServerFn` for secrets, database access, or other server-only logic.
- Keep the TanStack Start Vite plugin before the React plugin. The generated devtools plugin must remain first.

## Environment and Deployment

- No environment variables are required for the blank app.
- Use Node.js 20 or newer. Scaffolding was completed with Node.js 22 because the TanStack CLI rejects Node.js 18.
- Local development: `pnpm install`, then `pnpm dev` (port 3000).
- Production build: `pnpm build`.
- Preview the production build locally with `pnpm preview`.
- No deployment provider is configured. Before provider-specific deployment work, load `@tanstack/start-client-core#start-core/deployment` with TanStack Intent and follow its current adapter guidance.

## Known Gotchas

- The generated `package.json` contains `pnpm.onlyBuiltDependencies`; pnpm 11 warns that this field is no longer read and points to pnpm settings as its new home. It is preserved as generated pending a deliberate toolchain update.
- Do not use Next.js conventions such as `use server`, `app/layout.tsx`, or `getServerSideProps`.
- Do not enable `verbatimModuleSyntax`; the shipped Start guidance warns it can leak server bundles into client bundles.
